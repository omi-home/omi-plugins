# ADR-0004 — OMI Monitor: hai repo, profile và token mã hóa trong SQLite

- **Trạng thái:** Accepted. PO duyệt phạm vi qua ChangeRequest-0011 #280 (2026-11-20), gồm ARC-002, ARC-004, ARC-005 và ARC-006. Thay ADR-0002 D6 bằng D3 của ADR này, và sửa quy tắc "secret chỉ ở dạng tham chiếu env". Triển khai ở Feature-0035 #279 (Milestone-0012 #278, Epic-0002 #277). Vị trí lưu và quy tắc migration của D3 bị thay bởi [ADR-0007](./ADR-0007-profile-cap-may.md).
- **Ngày:** 2026-11-20
- **Người quyết định:** Product Owner (qua phiên Coordinator)
- **Nguồn:** [ChangeRequest-0011 #280](https://github.com/omi-home/omi-plugins/issues/280), section `architecture` (Decision record) và section Decision.

## Bối cảnh

PO cần một màn hình giám sát chạy local (OMI Monitor, Next.js) để theo dõi run/agent realtime, xử lý việc cần PO, quản lý profile và chỉnh cài đặt OMI, mà không tốn token của phiên Coordinator. Hiện tại:

- Repo plugin không có bước build, dependency chỉ `yaml` + `zod`. Plugin cài bằng marketplace (clone repo, không chạy `npm install` hay build).
- Profile nằm ở `<workspace>/.omi-plugins/omi.config.json` (ADR-0002 D6) và chỉ chứa tên biến env. Token nằm trong biến môi trường User, nên không thêm, sửa hay xóa profile từ giao diện được.
- `state.sqlite` (WAL, `node:sqlite`) do plugin sở hữu; mọi thao tác ghi đi qua `omi` CLI.

## Quyết định

| # | Chủ đề | Quyết định |
| --- | --- | --- |
| D1 | Hai repo | `omi-plugins` sở hữu dữ liệu, contract zod, migration, `redact` và mọi thao tác ghi. `omi-home/omi-monitor` (Next.js) chỉ là giao diện: **không mở `state.sqlite`**, không chép contract hay migration. Đọc: server web giữ **một** tiến trình `omi watch --output jsonl` (mỗi ~1s một dòng JSON = mô hình màn hình, có `protocolVersion`) và đẩy sang trình duyệt bằng SSE; không gọi GitHub trong vòng làm mới. Ghi: gọi lệnh CLI có `--output json` (`omi profile …`, `omi config …`); secret truyền qua **stdin**, không qua argv. Schema của mô hình màn hình và của output lệnh là zod contract trong plugin, xuất JSON Schema; `omi-monitor` sinh type từ đó. Lệch `protocolVersion` → web báo "cần cập nhật", không đoán. Bootstrap OMI cho `omi-monitor` riêng (workspace riêng, dùng chung Project #2); task của web app là Issue trong repo đó, cha là #280 (ARC-005). |
| D2 | Phân phối | `omi-monitor` build Next.js `output: "standalone"`; CI đính bản build dạng **`.tar.gz`** (giải nén bằng `tar` của hệ điều hành, không zip — ARC-002) cùng sha256 vào GitHub Release. Plugin ghim bản dùng trong `config/web.json` `{ version, asset, sha256 }`. `omi web`: lần đầu tải bằng `gh release download` (auth `gh` sẵn có), kiểm sha256, giải nén vào `<workspace>/.omi-plugins/web/<version>/`; lần sau dùng lại. Chạy `node server.js` bind `127.0.0.1`, cổng trống, sinh token phiên, mở trình duyệt với URL mang token; `Ctrl+C` dừng sạch, gồm cả tiến trình `omi watch` con. Nâng hay lùi bản web = PR sửa `config/web.json`. Bản cũ trong `web/` do `omi cleanup` dọn. Không bắt máy người dùng `npm install` hay build. |
| D3 | Profile trong DB | **Location replaced by [ADR-0007](./ADR-0007-profile-cap-may.md)** (vị trí lưu và quy tắc migration; hình dạng bảng, tên bất biến và CLI giữ nguyên). Nội dung gốc: profile chuyển vào bảng `profile` của `state.sqlite`: các field của contract `Profile` (`name`, `harness`, `disabled`, `auth`, `models[]`, `efforts[]`) cộng `secret_ciphertext`, `secret_iv`, `secret_tag`, `key_fingerprint`, `updated_at`. **Tên profile là bất biến** (ARC-006): không đổi tên được vì tên là khóa và là AAD của token mã hóa (D4); muốn đổi thì thêm profile mới và xóa profile cũ. Migration giữ cho state cũ mở được bằng bản mới. CLI: `omi profile list\|add\|edit\|remove\|set-token` (`--output json`); `set-token` đọc token từ stdin. `loadProfiles` và mọi nơi đọc profile chuyển sang DB. `omi profile import` chuyển đổi một lần, chạy lại an toàn: đọc `omi.config.json` (và section `profiles` của YAML nếu có), lấy token từ biến env đang khai báo, mã hóa vào DB, đổi file cũ thành `.bak`. Còn khai báo profile ở file sau khi import → `CONFIG_INVALID` hướng dẫn chạy import, không âm thầm chọn một bên. `omi doctor` kiểm master key có/đúng (fingerprint) và mỗi profile giải mã được token, không in giá trị. **Thay ADR-0002 D6** (vị trí lưu và quy tắc secret); `omi.config.yaml` vẫn là nguồn sự thật cho policy và không chứa `profiles`. |
| D4 | Mã hóa token | AES-256-GCM bằng `node:crypto` (không thêm dependency). IV 12 byte ngẫu nhiên mỗi lần ghi. AAD = tên profile (nên token không dùng lại được ở profile khác). Master key 32 byte (base64) nằm trong biến môi trường; `omi.config.yaml` chỉ chứa **tên biến** (`secrets.keyEnv`, ví dụ `OMI_SECRET_KEY`). `key_fingerprint` nhận ra key sai mà không cần giải mã. `omi secret init-key` sinh key và ghi vào biến môi trường User (Windows `setx`/registry, Linux chỉ hướng dẫn), không in key ra log. `omi secret rotate-key` giải mã bằng key cũ, mã hóa lại bằng key mới trong một transaction; key mới lấy từ biến `<keyEnv>_NEXT`. Lúc chạy agent: giải mã và gán `CLAUDE_CODE_OAUTH_TOKEN` (hoặc biến key tương ứng) **chỉ cho tiến trình con**; token đã giải mã được thêm vào danh sách `redact` của tiến trình, và không vào log, transcript, comment hay output JSON. Thiếu hoặc sai key → `OmiError` có mã trong `runtime/core/errors/` kèm hướng dẫn; mất key → nhập lại token. |
| D5 | Giới hạn bảo mật | Mã hóa bảo vệ trước việc lộ `state.sqlite` qua bản sao lưu hoặc copy file. Nó **không** chặn được tiến trình chạy cùng user (kể cả agent) đọc biến env master key hoặc gọi `omi` để giải mã; mức này không tệ hơn hiện tại (token đang là biến env User). ADR-0002 D5 vẫn đúng: cách ly env là cách ly cấu hình, không phải ranh giới bảo mật. Web: chỉ nghe `127.0.0.1`, kiểm `Host`/`Origin` (chống DNS rebinding và CSRF), mọi API cần token phiên (cookie HttpOnly đặt từ URL `omi web` mở), không log body request chứa secret, không bao giờ trả token về trình duyệt (ô hiện `********`, sửa = ghi đè). |

## Hệ quả

- Thay ADR-0002 D6 bằng D3; các quyết định khác của ADR-0002 giữ nguyên. Quy tắc "secret chỉ ở dạng tham chiếu env" nay chỉ còn đúng cho master key (D4); token profile nằm mã hóa trong DB.
- Workspace đang dùng phải chạy `omi secret init-key` và `omi profile import` **một lần**.
- `omi profile import` không xóa biến env token: các biến này giữ tới khi ChangeRequest-0004 #241 release (quy tắc tạm trong `AGENTS.md` của workspace) (ARC-004).
- #239 vẫn gộp policy về một file `omi.config.yaml` có mẫu và mô tả, nhưng không chứa `profiles` và thêm `secrets.keyEnv`.
- Thêm phụ thuộc phát hành: `omi web` cần một bản `omi-monitor` đã release; phải theo dõi `protocolVersion` giữa hai repo.
- Ngoài phạm vi: truy cập từ máy khác, nhiều người dùng, đăng nhập, macOS, điều khiển run từ web.
